# Content Script Writer

Turn an idea into something a person can actually stand up and film today.

Instructions are in English; **every spoken line, on-screen word and caption you write is in PT-BR**, unless the user's own material is in another language.

## What makes a script fail

Not weak writing. Three other things, in order of how often they kill it:

**The mold.** A script forced into hook → problema → solução → CTA sounds like every other script that used the same mold, and the audience has heard it ten thousand times. Structure should come from the *content*: a comparison wants two columns, a process wants steps, a mistake wants the wrong way then the right way, a story wants chronology. Pick the shape that fits the idea and the format, then time it. The mold is a fallback for when nothing better presents itself, not a default.

**Words nobody says out loud.** Scripts get written as prose and then read as speech, and the seams show — subordinate clauses, "além disso", "portanto", perfectly balanced sentences. Say the line out loud in your head. If it needs a breath in the middle that the punctuation does not give it, rewrite it.

**Writing a script the person cannot film.** A brilliant script requiring a second camera operator, a location, or a stat the user does not have is worth nothing. Check the constraints before writing, not after.

## Step 1 — Get the constraints

Ask only for what you cannot infer, and ask it in one message. Most of this usually arrives with the request, in a teardown from `viral-brand-analyst`, or in a profile file the user keeps in the project (see "The user's profile" below).

- **The source** — a teardown from `viral-brand-analyst`, research, an article, a transcript, a bare idea. If a teardown produced concepts, read them; they carry the beat structure and the mechanism, and you should not re-derive either.
- **Format and platform** — Reel, TikTok, Short, carousel, VSL, ad. This decides length, structure and grammar, so it is the one thing you genuinely cannot guess.
- **Who is on camera** — faceless with motion graphics, screen recording with voiceover, or the user on camera. If the user records faceless with voiceover after the fact, the script must survive without a face carrying it.
- **What they actually have** — a product to demo, real numbers, a personal story, footage. This is the difference between a filmable script and a wish.
- **The one thing** the viewer should leave with. If there are three, it is three videos.

If the source is a teardown, the mechanism is already named — build on that instead of starting over.

## Step 2 — Choose the shape

Read `references/formats.md` for the working structures and when each earns its place, and `references/hooks.md` for how to open. Do not load both if you already know the shape; the files are independent.

Match the shape to the idea:

| The idea is… | The shape that fits |
|---|---|
| A mistake people make | O jeito errado → por que dói → o certo |
| A process or method | Passos numerados, com o resultado logo no início |
| A comparison | Lado a lado, alternando, nunca um bloco depois do outro |
| A surprising fact | A afirmação, a prova, a consequência |
| A story | Cronologia, com a virada no meio |
| A demo | O resultado primeiro, depois como |
| A contrarian take | O consenso, por que está errado, o que fazer |

## Step 3 — Write it

Read `references/writing.md` for the craft — line rhythm, retention mechanics, on-screen text, how to write voiceover that sounds spoken, and the CTA problem.

Two rules that carry most of the weight:

**Write the spoken line verbatim.** Not "fala sobre o problema do deploy" but the actual words, punctuated the way they will be said. The user is going to read this into a microphone; a description is not a script and forces them to write it again.

**Time every beat and make the durations add up.** A beat that says `[0-3s]` and contains 40 words is a lie — that is 12 seconds of speech. PT-BR runs roughly **2,5–3 palavras por segundo** at natural narration pace. Count. A script whose timings do not survive contact with a stopwatch will be rebuilt in the edit, which wastes the work.

## Step 4 — Output

Use this structure. Adapt the beat names to the shape you chose rather than pasting generic ones.

```
ROTEIRO: [título curto e específico]
FORMATO: [Reel 9:16 · 32s · faceless com locução]
A IDEIA: [uma frase — o que o espectador leva embora]

[0:00–0:03] GANCHO
FALA: "[palavras exatas]"
TELA: [o que aparece]
TEXTO: [texto na tela, se houver]

[0:03–0:11] [nome da batida]
FALA: "[palavras exatas]"
TELA: [o que aparece]
CORTE: [tipo de corte, se importa]

[…]

LEGENDA:
[primeira linha carregando sozinha — é o que aparece antes do "mais"]
[resto]

SOM: [tratamento — locução seca, com sound design, silêncio antes do payoff]
PRODUÇÃO: [como isso vira vídeo — câmera no rosto, tela gravada + locução,
motion graphics; e com que ferramenta de edição o usuário trabalha, se souber]

ONDE ISSO PODE QUEBRAR:
[1–2 linhas honestas: o que exige gravação difícil, um dado que o usuário
precisa confirmar, uma afirmação que ele precisa poder defender]
```

That last section matters more than it looks. A script that quietly assumes a number the user does not have, or a claim they cannot back, is a trap — naming it costs two lines and saves a reshoot.

## Step 5 — Read it back

Before handing it over, run three checks. They take a minute and catch most of what would otherwise come back as feedback.

1. **Say the first line out loud.** If you would not say it to a friend, rewrite it.
2. **Add up the beat durations.** Do they match the stated total? Does each beat's word count fit its seconds at ~2,5–3 palavras/s?
3. **Cover the audio.** Does the video still make sense on mute, from the on-screen text alone? Most of the feed is silent. If it collapses, add text — do not just hope.

## On hooks

This skill exists partly to fight generic content, so a swipe-file of fill-in-the-blank openers ("Eu parei de fazer X e Y aconteceu", "Ninguém está falando sobre...") is the wrong deliverable. Those phrases were strong when they were new and are now audible as templates — the audience recognizes the shape before the sentence ends and scrolls.

What transfers is the **mechanism**: opening a loop, staking a disputable claim, naming an enemy, showing the result before the method, breaking an expectation. `references/hooks.md` covers these with real examples. Write a specific line for *this* video using one of them, and say which mechanism it uses so the user can judge it. Specificity is what makes a hook work — "seu deploy quebrou às 3 da manhã" beats any template, because it is about something.

Write 3 hook options per script. They should differ in **mechanism**, not in wording; three phrasings of the same idea is one option.

## Multiple scripts

When asked for several (a week of content, variations on a theme), vary the *shape*, not just the topic. Five scripts with the same structure read as five copies of one video, and the account starts to look like a template. Mix a demo, a mistake, a comparison, a story.

If they are for one campaign, one should carry the strongest claim and the others should support it — not five equal, interchangeable pieces.

## The user's profile

If the project has a file named `perfil.md` (or the user points to one), read it before Step 1. It carries the niche, the audience, who is on camera, the tone, words the user never says, and real numbers they can cite — everything that keeps scripts from coming out generic. Do not ask for anything already written there.

If no profile exists and this is the first script in the session, offer once, in one line, to create `perfil.md` from the answers to Step 1, so the next script starts with them. Do not insist.
